# PSX engine operating constraints

- Never fabricate prices, bars, news, eligibility, actions, outcomes or probabilities.
- Use public permitted sources; no protection bypass.
- This is experimental decision support. No automatic orders or live trading.
- Pure technical decisions and replay share decision_engine.decide and a completed session cutoff.
- Do not weaken data guards to recover signal coverage. Reconcile source data first.
- Preserve the tracked baseline database and actual portfolio during development. Test on isolated copies.
- Preserve immutable opportunities, frozen execution assumptions and legacy label definitions.
- Audit reliability and the 42-session v3 strategy were authorized for `main` on 2026-09-05. Runtime data still needs a durable destination and a verified restore; keep rolling official reconciliation current.
- Run unittest discovery, compilation and git diff checks before proposing changes.

See README.md and docs/AUDIT_IMPLEMENTATION.md for current behavior and unfinished acceptance gates.
Dated historical research, preferences and rationales are preserved verbatim in docs/history/CLAUDE-2026-09-05.md. They are historical evidence, not validated strategy performance.

## Current implementation state

- User requests: use plain language throughout the dashboard; test past signals for all tracked stocks; include verified KMI All Share stocks below PKR 50. Do not confuse the user's Codex usage reset with a change to that price limit.
- v4 fixes the obsolete 60-session weak-data flag: the complete 42-session contract must not automatically block all Buys. Each historical decision still uses only its preceding 42 sessions. Default evaluation is the latest 21 sessions, backed by 64 official sessions where available.
- The universe is 60 symbols as of 2026-09-09 on the user's instruction: the 50 curated names plus `config.CURATED_ADDITIONS` (IPAK, ASL, DCR, GHGL, POWER, CNERGY, FTSM, LOADS, FIBLM, EPCL). It was briefly 168. The 10 were chosen AFTER the 2026-09-08 backfill so each had real history: >=220 bars, median 20-day turnover above MIN_TURNOVER_PKR, a scored signal, then ranked on trend quality and score with a cap of two per sector.
- data_lower_price_stocks.json still holds all 135 verified symbols and is untouched — it is dated membership evidence, not a switch. Dropping a symbol from STOCKS does not delete its banked bars (all 168 symbols keep their rows in daily_ohlc, 161,675 in total), so re-adding any name is immediate and lossless. PSX label suffixes such as XD and NC are not part of the trading symbol.
- Top-ten candidates must have rising 10/20/40-session trends, positive momentum and buying flow, adequate volume, valid trade levels, and verified eligibility. Show fewer than ten when fewer qualify; never fill the list with weak names.

- Commit `678edd9` introduced versioned completed-session decisions, immutable opportunity outcomes, target-before-stop evaluation, atomic batches, source-quality gates, shared sizing, exchange-session handling, and regression CI.
- `technical_swing_short_v3` uses exactly 42 sessions, 10/20/40-session EMAs, and 10/21/41-session relative strength. Older bars cannot affect its decision.
- The latest 42-session decision window, 2026-07-07 through 2026-09-04, is reconciled to 2,100 official bars for all 50 symbols. Its initial smoke result was 29 Avoid, 18 Watch, 3 Hold, and zero Buy; do not weaken thresholds to manufacture candidates.
- A push race is not a database conflict. `678edd9` replaced the loop's reconcile-and-retry push with a bare `git push || exit 1`; on 2026-09-07 `news.yml` pushed `news_raw_24h.json` at 09:17 and the engine's 09:21 push was rejected, killing run 34105025926. `news.yml` never stages `psx_engine.db`, so that commit rebases cleanly. The push now retries with a PLAIN `git pull --rebase` — never `-X theirs`, which makes the loop's database win every conflict and silently discarded a regrade on 2026-08-13. A real database conflict still aborts and fails loudly. Do not simplify this back to a single push.
- `notify.py` sorted on `final_score` without the `None` guard `excel_export` already had, so the email step raised `'<' not supported between NoneType and float` on every run. It only appeared once the universe reached 168 symbols and produced no-data rows (24 of 168 in the 2026-09-07 14:28 cycle).
- The engine banks only the completed cutoff session's bars; nothing intraday reaches daily_ohlc. The v3 rewrite stopped calling psx_market_watch from main.py, and the unreachable wiring (`_bank_official_hl`, `_is_live_session`, `_same_bar`, the unused import) was removed on 2026-09-10. `psx_market_watch.py` itself stays — `tools/prepare_recent_history.py` and `mw-probe.yml` use it. Restoring intraday banking would need a deliberate decision, not a re-import: it would put partial bars in the same table the completed-session contract reads.
- session_calendar.last_completed() cannot see PSX closures while config.EXCHANGE_HOLIDAYS is empty, so full_run confirms the cutoff against the exchange: psx_historical.fetch_day returns an empty table for a non-trading day, and _resolve_cutoff walks back to the last day PSX actually reports. A feed outage is deliberately NOT treated as a run of holidays — if nothing answers within the walk the original cutoff is kept, because rewinding the decision window is worse than standing still. On 2026-09-09 the exchange was shut and the loop still ran 24 cycles: 4,032 rows carrying the 2026-09-08 close, stamped `good`, zero of 168 symbols moving all day. Those rows are preserved with data_quality prefixed `QUARANTINED no-session 2026-09-09 | `; decisions had no rows for that session and opportunities was empty, so the v3 path had refused it on its own.
- A running job's shell script is baked in when the job starts, so a workflow fix never reaches the loop already running. Cancel it and dispatch, or the old script keeps going for hours.
- The 2026-09-08 five-year backfill took daily_ohlc from 66,247 to 161,675 bars: symbols with >=250 sessions went 49 -> 153, median bars 65 -> 1,198, history back to 2021-09-01. Before it, 119 of the expansion symbols had ~65 bars, so EMA200, the 250-bar beta window and the 520-bar chart read were all unavailable for them. Seven legacy bars (5 JVDC, BNL, ENGROH, newest 2024-07-15) still carry a close outside their own high-low range; bar_error() catches this shape for new writes but never re-checks old rows, and tools/reconcile_data.py refuses to run on the tracked database by design.
- momentum.py never applied MIN_TURNOVER_PKR, so on 2026-09-08 the panel surfaced FTMM at +9.98% on a 302,798 PKR median daily turnover. The floor is applied now, and the caption no longer prints the 2026-08-17 beat rates beside names the original 50-symbol measurement never covered.
- A passing test suite validates software behavior, not forecast accuracy or profitability. Keep probabilities uncalibrated until a frozen prospective cohort has enough independently resolved opportunities.
